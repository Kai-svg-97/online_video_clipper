# YouTube 콘텐츠 관리 GUI 애플리케이션 기획서

## 프로젝트 명
YouTube Content Manager & Downloader

---

## 개요
본 프로젝트는 유튜브 콘텐츠를 즐겨찾기 기반으로 관리하고 다운로드 및 라이브러리화할 수 있는 GUI 애플리케이션을 개발한다. 단순 다운로드 툴을 넘어 개인 유튜브 콘텐츠 관리 플랫폼을 목표로 한다.

---

## 주요 기능 요약

- 즐겨찾기 관리 (제목, 태그, 설명, 개인 메모)
- 다운로드 및 다운로드 이력 관리
- 카테고리 기반 저장
- 태그 및 검색 필터링 (SQLite FTS5 전문 검색)
- 썸네일 UI 및 크기 조절 (그리드 / 리스트 뷰 전환)
- 탐색기(TreeView) 기반 UI
- 자막/썸네일/메타데이터 다운로드
- 클립보드 자동 감지
- 병렬 다운로드 및 큐 관리
- 클립 구간 추출 (ffmpeg 연동)
- 채널 구독 & 신규 영상 모니터링
- 플레이리스트 / 채널 일괄 다운로드
- 내보내기 / 가져오기
- 통계 대시보드

## 기능 상세

### 1. 즐겨찾기 & 라이브러리 관리

- URL 입력 또는 클립보드 자동 감지로 영상 추가
- 제목, 태그, 카테고리, 개인 메모 편집
- 시청 여부(watched) 표시 및 필터
- 즐겨찾기 목록 JSON/CSV 내보내기
- 유튜브 플레이리스트 URL로 일괄 임포트
- 브라우저 북마크(HTML) 임포트

### 2. 다운로드

- 단일 영상 다운로드 (품질/포맷 선택: mp4, mkv, mp3 등)
- 플레이리스트 전체 다운로드 (이미 다운로드된 항목 자동 스킵)
- 채널 아카이브 모드 (전체 또는 날짜 범위 지정)
- 병렬 다운로드 큐 (동시 다운로드 수 설정)
- 메타데이터 / 자막 / 썸네일 개별 다운로드
- 다운로드 실패 시 자동 재시도 (재시도 횟수 설정)

### 3. 클립 구간 추출

- 영상의 특정 구간 타임스탬프 북마크 저장
- ffmpeg로 해당 구간만 추출·저장
- 클립 미리보기 썸네일 자동 생성

### 4. 재생 연동

- 더블클릭 → 외부 플레이어(VLC, mpv, Windows 기본 플레이어) 실행
- 마지막 재생 위치 기억 (`last_position_sec` SQLite 저장)
- 온라인 스트리밍 재생 (다운로드 없이 재생)
- **앱 내 고화질 스트리밍 재생 (v1.32)**: 기본 화질은 "자동 (최고 화질)" = 1080p.
  영상과 소리가 분리돼 제공되는 고화질도 **파일을 받지 않고** 실시간으로 합쳐 재생한다.
  회선이 버티지 못하면 자동으로 "받아 두고 재생"으로 내려간다.

### 5. 채널 구독 & 모니터링

- 채널 URL 등록 → RSS 또는 폴링으로 신규 영상 자동 감지
- 채널별 자동 다운로드 규칙 (키워드 조건, 최소/최대 재생시간 필터)
- 시스템 트레이 알림: 새 영상 발견 시 알림

### 6. 검색 & 필터

- **전 속성 검색**: 검색어를 입력하면 영상 제목·태그·설명·메모·요약·노래 정보(가수/앨범/제목/발매년도)·가사에서 찾는다. 부분 일치이므로 "가정부"로 "가정부라고"도 찾는다.
- **일치 속성 표시**: 각 결과 카드 하단에 어느 속성에서 일치했는지 배지로 표시해, 그 영상이 왜 검색됐는지 바로 알 수 있다.
- 복합 필터: 날짜 범위, 영상 길이, 채널, 다운로드 여부, 즐겨찾기
- 저장된 검색 쿼리 (북마크된 필터)
- 가사 검색은 최상위 카테고리가 음악(Music/음악/노래)인 영상으로 한정한다.

### 7. 통계 대시보드

- 총 다운로드 수 및 누적 용량
- 카테고리/태그별 분포 차트
- 최근 활동 로그

### 8. 설정

- 기본 다운로드 경로
- 동시 다운로드 수 (1~8)
- 기본 품질/포맷 프리셋
- ffmpeg 실행 파일 경로
- 클립보드 감지 활성화 여부
- 프록시 설정
- yt-dlp 자동 업데이트 확인
- **가사 출처 관리**: 노래 가사를 조회할 사이트 목록(LRCLIB·Genius·멜론·벅스·지니 등)의 사용 여부·조회 순서 조정, 커스텀 출처 추가/삭제

### 9. 노래 정보

노래 영상에 대해 가수·앨범·제목·가사를 조회·관리한다.

- **노래 탭**: 상세화면 4번째 탭. 가수/앨범/노래 제목/발매년도 + 가사 섹션으로 구성.
- **자동 판별 + 수동 토글**: YouTube Music 카테고리 또는 음악 메타데이터로 노래를 자동 감지하고, "노래로 표시" 토글로 수동 지정도 가능.
- **가사 병행 표기**: 비한국어 노래는 원문 1줄 + 한글 번역 1줄을 병행 표기(무료 웹번역). 한국어 노래는 원문만.
- **관리형 출처 체인**: 주요 가사 사이트를 레지스트리로 관리하고, 우선순위 순으로 이어서 조회해 부족한 항목을 채운다. 참조 가능한 출처가 늘어나면 정보가 보강된다.
- **등록 시 조회 + 정보 갱신**: 등록 시 노래 정보를 조회해 기록하고, 정보 갱신(⟳) 버튼으로 재수집한다. 상세화면에서 가사는 가사 검색 버튼을 눌러야 조회한다(자동 조회 안 함).
- **가사 검색 후보 목록**: 가사 검색 버튼을 누르면 가사 영역이 후보 목록으로 바뀌고, 조회할 출처마다 **|출처|가수|제목|가사 첫째 줄|싱크여부|** 한 줄이 먼저 '조회중'으로 뜬다. 결과가 확인되는 출처부터 그 자리에서 채워지므로 전 출처가 끝나기를 기다릴 필요가 없다. 결과가 없는 출처는 '결과 없음'으로 남아 고를 수 없다. 원하는 줄을 고르고 '이 가사 사용'을 누르면 그 가사(시간 정보 포함)가 반영되고, '닫기'를 누르면 기존 가사로 돌아간다.
- **출처당 여러 곡을 나열**: 같은 제목의 다른 가수 곡이 흔하므로 출처마다 한 곡이 아니라 검색된 여러 곡을 각각 한 줄씩 보여준다(기본 출처당 최대 10곡). 가수를 지정해 검색해도 제목만으로 한 번 더 훑어 다른 가수의 같은 제목 곡까지 목록에 올린다. 상한을 두는 이유는 가사 사이트에서 곡마다 페이지를 한 번씩 읽어와야 해, 무제한으로 두면 검색이 몇 분씩 걸리기 때문이다.
- **인기순 우선 정렬**: 조회수를 알려주는 출처(Genius)는 **조회수가 많은 곡부터** 나열한다. 조회수를 주지 않는 출처(LRCLIB)는 **영상 길이와 가장 비슷한 곡부터** 올려 같은 녹음일 가능성이 높은 후보를 위로 보낸다. 국내 사이트(멜론·벅스·지니)는 검색 결과 순서가 이미 그 사이트의 인기·정확도 랭킹이므로 그대로 따른다. 상한(10곡)은 정렬한 **뒤에** 적용하므로 인기 곡이 잘려 나가지 않는다. 각 줄에 마우스를 올리면 조회수·곡 길이·줄 수를 볼 수 있다.
- **단건 등록 시 자동 보강**: 영상을 한 건씩 등록하면 음원용 영상은 **가사**를, 그 외 영상은 **Gemini 요약**을 백그라운드에서 자동으로 채운다(설정으로 끌 수 있고 기본 ON). 판정 기준은 등록 시 기록된 노래 여부(YouTube Music 카테고리 또는 음악 메타데이터)다. 가사를 찾지 못하면 요약으로 대체하지 않는다. 재생목록·채널 일괄 가져오기는 대상이 아니다(영상당 수십 초가 걸려 대량 처리에 부적합). 요약은 YouTube 로그인 쿠키가 필요하다.
- **더블클릭 편집**: 가수/앨범/제목/발매년도·가사 각 영역을 더블클릭해 직접 수정할 수 있으며, 수정한 값은 이후 갱신에서 덮어쓰지 않는다.

### 가사 자막

- 노래 영상 재생 중 가사를 영상 위 자막으로 표시한다(원문 + 한글 번역 병행).
- **시간 정보가 있는 가사에 한해서만** 자막·싱크 기능이 활성화된다. 시간 정보는
  LRCLIB의 싱크 가사에서만 얻을 수 있으며, 없을 경우 '싱크 가사 찾기'로 재탐색한다.
- 가사와 영상의 어긋남은 **시작 오프셋 하나**로 보정한다(±30초). 배속·구간별 보정은
  범위 밖이다.
- 자막은 어떤 영상 배경에서도 읽히도록 외곽선 텍스트로 그리고, 전체화면에서 글자가
  커진다. 번역은 원문보다 한 단계 작게 표시한다.
- 노래 탭의 가사 목록은 재생에 맞춰 현재 줄을 강조하고, 줄을 클릭하면 그 시점으로 이동한다.
- 자막 글자 크기와 세로 위치를 Ctrl(+Shift) + 휠·방향키로 조절하고 전역 설정으로 유지한다.

```
┌─────────────────────────────────────────────────────────────────┐
```

## 배포 패키지

| 플랫폼  | 형식                          | 도구                          |
|---------|-------------------------------|-------------------------------|
| Windows | `.exe` 설치 파일              | PyInstaller + Inno Setup      |
| Linux   | `.AppImage` (이식성 최우선)   | PyInstaller + appimagetool    |

**핵심 원칙:**

- 사용자는 Python, ffmpeg, yt-dlp를 별도 설치할 필요 없음
- DB, 설정, 로그는 OS 표준 사용자 데이터 경로에 저장 (앱 폴더 아님)
  - Windows: `%APPDATA%\YouTubeContentManager\`
  - Linux: `~/.local/share/YouTubeContentManager/`

## UI/UX 개선 사항 (v0.4 반영)

### 썸네일 자동 다운로드
- `AddVideoHandler`에서 yt-dlp 메타데이터의 `thumbnail` URL을 가져와 `THUMBNAIL_DIR/{video_id}.jpg`로 저장
- `YtDlpAdapter.download_thumbnail(video_id, thumbnail_url)` 메서드 추가
- `VideoAggregate.update_metadata(thumbnail_path=...)` 호출로 경로 저장
- 썸네일 다운로드 실패 시 무시하고 진행 (선택적)

### 영상 목록 — 카테고리 열 표시
- `VideoDTO`에 `category_name: str` 필드 추가 (기본값 `""`)
- 핸들러에서 카테고리 목록을 조회해 `_to_dto(agg, cats)` 형태로 전달
- 테이블 뷰: "카테고리" 컬럼 추가
- 목록 뷰 delegate: 채널·재생시간 옆에 카테고리명 표시

### 인플레이스 상세 보기 (모달 → 인라인 전환)
- `LibraryPanel` 우측 콘텐츠 영역을 `QStackedWidget`으로 변경
  - 페이지 0: 기존 비디오 목록 (툴바 + 뷰 전환)

### v1.1 — 구독 채널 UX 통합

1. **구독 채널 트리 + 피드 통합**: 별도 "구독 피드" 사이드바 메뉴를 제거하고, 라이브러리 좌측 YouTube 트리에 "구독 채널" 폴더와 "전체 구독 피드" 노드를 둔다. 채널 노드를 클릭하면 해당 채널의 최신 영상이 메인 영역에 피드 카드로 표시된다(`fetch_channel_videos`). 구독 채널 목록은 채널 모니터링의 구독을 공유하며, yt-dlp 가져오기에 페이지네이션을 적용해 전체 구독이 노출된다.
2. **재생목록 내 태그 필터**: 재생목록을 본 상태에서도 태그를 클릭하면 재생목록∩태그 교집합으로 좁혀 볼 수 있다.
3. **검색 안정화**: 검색어를 FTS5 구문으로 안전 변환해 `-`·`(` 등 특수문자 입력 시 구문 오류가 발생하지 않는다.
4. **다운로드 이력 정리**: 완료 이력 탭은 영상 파일만 표시(썸네일·.part 제외)하고 완료/실패를 배지로 구분한다. 통계의 총 용량은 경로 중복 제거 + 영상 파일 한정으로 정확히 집계한다.

### v1.2 — 구독 피드 채널 표시 & 채널 목록 뷰

1. **YouTube 구독 가져오기 안정화**: 구독 일괄 등록이 멱등(이미 등록된 채널 재등록 시 `UNIQUE` 충돌 없이 건너뜀)하고, API가 제공한 채널 id·name을 그대로 사용해 채널당 메타데이터 재조회 없이 빠르게 완료된다. → 진행 중 멈춤·동기화 누락 해소.
2. **전체 구독 피드 채널명 표시**: 피드 카드 썸네일 좌측 하단에 채널명 배지를 표시하고 제목 아래 채널명 라벨을 둔다. yt-dlp 플랫 추출은 구독 피드에서 채널 정보를 주지 않으므로, 영상 ID로 YouTube Data API `videos.list(part=snippet)`를 배치 역조회해 채널명을 채운다(미인증 시 구독 저장소 channel_id→이름 매핑으로 보강).
3. **개별 채널 피드는 채널명 숨김**: 특정 채널의 영상 목록에서는 이미 채널을 알고 있으므로 카드의 채널 배지·라벨을 표시하지 않는다(`show_channel` 토글).
4. **"구독 채널" 노드 = 채널 목록 그리드**: 좌측 트리의 "구독 채널" 노드를 클릭하면 등록된 채널을 아바타 + 구독자수 + 영상수 카드 그리드로 보여준다(YouTube API `channels.list(part=snippet,statistics)`). 채널 카드를 클릭하면 해당 채널 영상 피드로 이동한다. "구독 채널" 노드에는 자식이 있을 때 펼침 세모(▶/▼)가 표시된다.
5. **피드 그리드 리사이즈 재정렬**: 카드 그리드가 창 너비 변화에 따라 열 수를 재계산해 재배치된다(`resizeEvent` + 한 칸 폭 `minimumSizeHint`).

### v1.3 — 영상 목록 통일 · 상세화면 YouTube화 · 태그 스코핑

1. **영상 목록 단일 클릭 진입 + 미리보기 패널 제거**: 카테고리·재생목록·피드·채널 어디서든 영상을 **한 번 클릭**하면 곧바로 상세화면으로 전환한다(기존 더블클릭 폐지). 단일 클릭으로 중복되던 우측 미리보기 패널은 제거한다. Ctrl/Shift 클릭은 다중 선택·드래그 재정렬을 위해 선택 동작으로 유지한다.
2. **스트리밍 전용 상세**: 라이브러리에 저장되지 않은 구독 피드/채널 영상은 URL을 직접 스트리밍 재생하는 상세화면으로 연다(`load_stream`). 로컬 파일이 없으므로 클립 추출·메모·태그 편집은 비활성화한다.
3. **상세화면 YouTube 시청 페이지 레이아웃**: 좌측에 큰 플레이어와 그 아래 제목·채널·조회수·업로드일·태그·설명, 하단에 다운로드/메모/클립 탭을 두고, 우측에 연관 영상 목록을 둔다.
4. **클릭 가능한 타임라인(챕터)**: 설명에서 `MM:SS`/`HH:MM:SS` 타임스탬프를 추출(2개 이상일 때)해 챕터 목록으로 렌더하고, 클릭 시 `InlinePlayer.seek_to_ms`로 해당 위치로 재생 이동한다.
5. **컨텍스트별 연관 영상 목록**: 우측 목록은 보고 있던 분류에 따라 달라진다 — 카테고리/재생목록 영상은 현재 보고 있던 목록(같은 카테고리·재생목록, 자기 자신 제외), 피드/채널 영상은 같은 채널의 최근 영상(현재 로드된 피드 기준). 연관 영상 클릭 시 로컬/스트리밍 상세로 재진입한다.
6. **인기 태그 트리 스코핑**: 인기 태그를 현재 트리 노드 범위로 집계한다 — 카테고리는 해당 서브트리, 재생목록은 그 영상들, 둘 다 없으면(로컬 루트) 라이브러리 전체. 구현: `IVideoRepository.list_tags_with_counts(category_ids=, video_ids=)` 스코프 인자 + `GetTagsQuery` + `LibraryViewModel.refresh_scoped_tags()`. 로컬 태그가 없는 피드/채널 뷰에서는 인기 태그 패널을 숨긴다.

### v1.4+ — 사이드바 트리 정리 & 통계 채널 섹션

1. **접을 수 있는 YouTube 구독 섹션**: 좌측 트리에서 로컬 섹션과 YouTube 구독 섹션을 나누던 수직 스플리터를 제거하고, 삼각형(▸/▾) 토글 바로 대체한다. YouTube 구독 섹션은 **기본적으로 접혀(숨겨져)** 있고 토글 바를 눌러 펼친다. 접혀 있을 때는 로컬 카테고리 트리가 그 공간을 차지한다.
2. **트리 기본 1레벨 표시**: 모든 트리(로컬·YouTube)는 로드 후 최상위(1레벨) 항목만 보이고 하위는 접힌 상태로 시작한다. 하위는 사용자가 펼침 화살표를 눌러야 나타난다.
3. **통계 — 채널별 카테고리 섹션**: 통계 대시보드에 채널 섹션을 추가한다. 라이브러리 영상을 **업로더 채널별**로 묶고, 각 채널이 속한 **카테고리 전체 경로 + 영상 수**를 나열한다(예: `IT채널 : IT > News (3), IT > Device (2)` / `AI초보 : AI > Coding > Claude Code (12), AI > Coding > Codex (5)`). 카테고리 링크를 클릭하면 좌측 카테고리 트리를 클릭한 것과 동일하게 라이브러리 해당 카테고리로 화면 전환한다. 이후 **뒤로가기**를 누르면 라이브러리 자체 탐색 이력을 먼저 되짚고, 소진되면 통계 화면으로 복귀한다. 집계는 `videos`를 `channel_name`·`category_id`로 GROUP BY(카테고리 지정 영상 한정)하고, 카테고리 경로는 부모 체인을 거슬러 조립한다.

### v1.5+ — 구독 채널 재동기화

1. **"구독 채널" 노드 새로고침 메뉴**: 좌측 YouTube 트리의 "구독 채널" 노드를 **우클릭하면 컨텍스트 메뉴 맨 위에 "⟳ 새로고침 (YouTube 구독 재동기화)"** 항목이 뜬다. 클릭하면 `MonitoringViewModel.import_from_youtube()`로 YouTube 구독 전체를 다시 조회해 로컬 DB에 반영한다(멱등 등록이라 기존 채널은 건너뛰고 새 채널만 추가). 완료 시 `subscriptions_changed`로 좌측 트리가, `import_yt_finished`로 채널 카드 그리드가 각각 갱신돼 유튜브 웹에서 새로 구독한 채널이 즉시 나타난다. → 기존에는 구독 목록이 로컬 DB 스냅샷이라 채널 모니터링 패널의 "가져오기" 버튼으로만 재동기화할 수 있었던 불편 해소.

### v1.8+ — 등록 시 요약·가사 자동 보강

1. **성격에 따른 자동 보강**: 영상을 단건으로 카테고리에 등록하면 등록 직후 백그라운드에서 한쪽만 채운다 — 음원용 영상이면 상세 "노래" 탭의 **가사**를, 그 외 영상이면 "요약" 탭의 **Gemini 요약**을 채운다. 노래 영상의 가수·앨범·제목·발매년도는 등록 시점에 이미 기록되므로 실질적으로 가사만 추가된다.
2. **폴백 없음**: 가사를 찾지 못해도 요약으로 넘어가지 않는다. 이미 값이 있는 영상은 건너뛴다.
3. **일괄 임포트 제외**: 재생목록·채널 일괄 가져오기는 대상이 아니다. Gemini 요약 추출이 영상당 브라우저를 띄워 수십 초 걸리므로 수백 건 임포트에 걸면 끝나지 않는다.
4. **직렬 실행 + 상태 표시**: 보강은 동시 1건으로 직렬화하고(브라우저 병렬 실행 방지), 진행·실패를 상태바에 표시한다. 완료 시 그 영상 상세가 열려 있으면 즉시 반영된다.
5. **설정 토글**: 설정 일반 섹션의 "등록 시 요약·가사 자동 채우기"로 끌 수 있다(기본 ON). 요약은 YouTube 로그인 쿠키가 필요하며 Chrome 127 이상은 쿠키 파일을 직접 등록해야 한다.

### v1.9+ — 밝은 테마 전환 & 트리 재설계

1. **기본 테마를 밝은 중간 톤으로**: 화면 전체가 너무 어둡고 창 배경·패널·카드가 서로 구분되지 않던 문제를 해결한다. 새 `mist` 팔레트를 기본값으로 하며, 계층 간 명도 차이를 눈에 보이는 수준으로 벌린다. 기존 어두운 테마 6종은 설정에서 계속 선택할 수 있다.
2. **좌측 사이드바가 패널로 분리**: 사이드바가 창 배경과 같은 색이라 경계가 없던 문제를 고친다. 이제 한 단계 밝은 면과 경계선으로 구분된다.
3. **칩·활성 태그 바가 테마를 따르도록**: 태그 칩과 활성 태그 바는 색이 코드에 고정돼 있어 어떤 테마를 골라도 어두운 색으로 남았다. 테마 색상에서 파생하도록 바꾼다. 단 "영상 없음" 경고 뱃지와 YouTube 강조색은 의미·브랜드 색이라 유지한다.
4. **태그·카테고리 색상 고정**: 같은 태그가 앱을 켤 때마다 다른 색으로 표시되던 문제를 수정한다. 이제 이름이 같으면 항상 같은 색이다.
5. **카테고리 트리 외형 재설계**: 둥근 행 배경, 카테고리별 색상 점, 우측 정렬 개수 뱃지, 즐겨찾기 별, 넉넉한 행 높이, 계층을 보여주는 들여쓰기 가이드선을 적용한다. 펼침·드래그&드롭·컨텍스트 메뉴 등 기존 동작은 그대로 유지된다.
6. **불필요한 아이콘 제거**: 사이드바 상단의 장식용 로고와, 설정 버튼과 기능이 겹치던 계정 아이콘을 없앤다.

### v1.14+ — 번들 YouTube OAuth 로그인

기존에는 사용자가 직접 Google Cloud Console에서 OAuth Client ID/Secret을 발급받아
설정 화면에 입력해야 했다(소수의 지인에게만 배포하는 앱 특성상 매번 반복하기엔
번거롭고 실수하기 쉬운 절차). 이제 배포자가 소유한 Desktop OAuth 클라이언트를
빌드에 한 번만 번들하고, 사용자는 `Google 계정으로 연결` 버튼 하나로 인증한다.

1. **Client ID/Secret 입력 제거**: 설정 화면에 더는 Client ID·Client Secret 입력란이
   없다. 사용자는 어떤 OAuth 클라이언트 값도 보거나 입력하지 않는다.
2. **시스템 브라우저로만 로그인**: 연결 버튼을 누르면 기본 브라우저가 열려 Google의
   로그인·동의 화면에서 진행된다. 앱은 Google 계정 비밀번호를 절대 처리하지 않는다
   (Desktop/PKCE + loopback 리다이렉트, 임베드 웹뷰 없음).
3. **소수 배포 대상 "미확인 앱" 경고는 운영 설정 사항**: Google이 표시하는
   "확인되지 않은 앱" 경고는 앱 내 오류가 아니라 Google Cloud OAuth 동의 화면의
   테스트 사용자 목록에 관련된 정상 동작이다.
4. **최초 연결 후 재시작 안내**: 연결에 성공하면 채널명과 함께 "앱을 다시 시작하면
   모든 YouTube 연동 기능이 활성화됩니다" 안내가 표시된다. 이번 작업 범위에서는
   이미 생성된 핸들러를 실행 중에 다시 묶는 처리는 하지 않는다 — 재시작이 활성화
   경계다.
5. **연결 해제 시 로컬 토큰 삭제**: `연결 해제`를 누르면 저장된 사용자 토큰이
   로컬(keyring 우선, 파일 폴백)에서 삭제되고 YouTube API 의존 기능은 다시
   비활성/폴백 상태로 돌아간다.
6. **번들 클라이언트 미포함 시 graceful 비활성화**: 개발/미배포 빌드처럼 OAuth
   클라이언트 설정이 없는 경우에도 앱은 정상적으로 시작되며, 연결 버튼만
   비활성화되고 "배포자에게 문의하세요" 안내가 뜬다.
7. **기존 브라우저 쿠키 인증과는 별개**: 구독 피드/Gemini 요약처럼 브라우저 쿠키
   기반으로 동작하던 기능은 이번 변경의 영향을 받지 않는다 — YouTube Data API용
   OAuth와 브라우저 프로필 쿠키는 화면상으로도 별도 섹션으로 계속 구분된다.

### v1.15+ — 가사 자막 시작 시각 직접 보정

영상과 가사 타이밍이 어긋날 때, 영상 위 자막(💬) 단축키·메뉴만으로 보정해야 했던
기존 방식에 더해 노래 탭에서도 직접 조정할 수 있게 한다.

1. **노래 탭 입력 필드**: '가사' 옆에 현재 보정값을 초(0.25초 단위, ±30초)로
   보여주는 입력 필드가 있다. 시간 정보가 있는(싱크) 가사에서만 나타나고, 없으면
   기존처럼 '싱크 가사 찾기(⏱)' 버튼이 대신 뜬다.
2. **`,`/`.` 단축키 추가**: 영상 위 자막 조정 단축키 `[`/`]`에 더해 `,`(빠르게)·
   `.`(늦게)로도 같은 조정을 할 수 있다.
3. **양방향으로 즉시 동기화**: 탭 입력 필드로 바꾼 값은 재생 중인 영상의 자막
   위치에 바로 반영되고, 반대로 영상 위에서 단축키·우클릭 메뉴로 바꾼 값도 탭의
   입력 필드에 즉시 반영된다. 저장은 기존과 동일하게 500ms 후 디바운스된다.

### v1.16+ — 라이브러리 가져오기/내보내기

모은 카테고리·영상·노래 가사(가사·싱크) 정보를 다른 사람에게 전달하거나 백업할
수 있게 한다. 설정 화면에 새 섹션을 추가한다.

1. **내보낼 카테고리를 고를 수 있다**: 체크트리에서 카테고리를 선택하면(부모를
   체크하면 하위 카테고리도 함께 선택된다) 그 안의 영상·태그·설명·메모·노래
   정보(가사 원문·번역·타이밍·싱크 오프셋)가 파일 하나(`.ovcpkg`)로 내보내진다.
2. **가져올 카테고리도 고를 수 있다**: 패키지를 열면 그 안의 카테고리 체크트리가
   뜨고, 원하는 것만 골라 가져올 수 있다.
3. **이름이 같은 카테고리는 합쳐진다**: 가져올 카테고리와 이름이 같은 카테고리가
   이미 있으면 새로 만들지 않고 그 카테고리로 합쳐 넣는다.
4. **이미 있는 영상은 정보를 병합한다**: URL이 같은 영상이 이미 있으면 새로
   만들지 않고 기존 영상에 정보를 채워 넣는다. 태그는 항상 합쳐진다(둘 다 남음).
5. **값이 다른 항목은 파일 탐색기처럼 골라서 판단한다**: 제목·메모·설명·카테고리·
   가수·앨범·노래 제목·발매년도·가사·싱크 오프셋 중 기존 값과 가져올 값이 다른
   항목만 화면에 나열된다. 각 항목은 기존 값과 가져올 값이 **각각 채워져 있는지
   비어있는지**를 함께 보여줘, 어느 쪽을 선택해야 할지 쉽게 판단할 수 있게 한다.
   한쪽이 비어있으면 채워진 쪽이 기본으로 선택되고, 둘 다 채워져 있으면 기존
   값을 유지하는 쪽이 기본이다(둘 다 원하면 언제든 바꿀 수 있다). "전체 가져오기값
   사용"/"전체 기존값 유지" 버튼으로 한꺼번에 정할 수도 있다.
6. **완전히 같은 영상은 아무것도 물어보지 않는다**: 값이 하나도 다르지 않으면
   화면에 나타나지 않고 조용히 넘어간다.

### v1.17+ — 추천 영상 스트립 (목록 아래 접이식)

지금 보고 있는 영상 목록과 관련 있을 만한 YouTube 영상을 목록 아래에 나열하고,
좌측 카테고리로 끌어다 놓아 바로 담을 수 있게 한다.

1. **목록 아래 접이식 스트립**: 영상 목록과 추천 영역 사이에 스플리터 바가 있어
   끌어서 높이를 조절할 수 있고, 바 왼쪽 삼각형(▾/▸) 버튼으로 추천 영역을 접거나
   펼친다. 접어도 바는 남아 언제든 다시 펼칠 수 있으며, 접힘 상태와 높이는 다음
   실행에도 유지된다.
2. **현재 목록을 기준으로 추천한다**: 지금 화면에 뜬 영상들의 제목·태그·채널에서
   대표 검색어를 뽑아 YouTube에서 후보를 찾는다. 카테고리를 바꾸면 그 목록에 맞춰
   추천도 자동으로 갱신되고, 바 오른쪽 ⟳ 버튼으로 즉시 다시 받을 수도 있다.
3. **검색창에 낱말을 넣으면 그 낱말의 YouTube 검색 결과가 뜬다**: 카테고리에 등록된
   영상을 검색하면, 위 목록은 내가 담아 둔 영상을 보여 주고 아래 스트립은 **같은
   검색어로 YouTube를 찾은 결과**로 채워진다(헤더에 `"검색어" YouTube 검색 결과`로
   표시). 목록에서 검색어를 짐작하지 않고 입력한 낱말을 그대로 쓰며, **내 라이브러리
   검색 결과가 0건이어도 YouTube 결과는 뜬다** — 없을 때가 오히려 찾아서 담고 싶은
   순간이다. 검색어를 지우면 다시 목록 기반 추천으로 돌아온다.
4. **이미 담아 둔 영상은 추천하지 않는다**: 라이브러리에 이미 있는 영상은 후보에서
   빠지므로 목록에 새로운 영상만 뜬다.
5. **드래그해서 카테고리에 담는다**: 추천 카드를 좌측 트리의 카테고리로 끌어다
   놓으면 그 카테고리로 등록된다. "로컬" 루트에 놓으면 미분류로 등록된다.
   우클릭 메뉴의 "카테고리에 추가"로도 같은 일을 할 수 있고, 카드를 클릭하면
   등록하지 않고 스트리밍으로 먼저 볼 수 있다.
6. **접혀 있으면 조회하지 않는다**: 추천 영역을 접어 두면 네트워크 조회도 하지
   않으므로, 추천 기능이 필요 없는 사용자는 접어 두면 된다.
7. **인증이 없어도 동작한다**: 추천 검색은 YouTube 로그인·API 키 없이도 동작한다.
   조회수·게시일 같은 부가 정보는 YouTube API가 연결돼 있으면 함께 채워진다.
8. **카드 그리드 화면에서는 뜨지 않는다**: 구독 피드·구독 채널 목록·폴더 화면은
   그 자체가 카드 그리드이므로 추천 스트립을 숨긴다.

### v1.18+ — 앨범 보기 (음악 카테고리)

최상위 카테고리가 음악(Music·Song·음악·노래·뮤직)인 곳에서 모아 둔 노래를
**앨범 단위**로 보고 재생한다.

1. **보기 유형에 '앨범'(💿)이 생긴다**: 음악 계열 카테고리를 고르면 목록 보기 버튼
   (⊞ 아이콘 / ☰ 리스트 / ⊟ 표) 옆에 앨범 버튼이 나타난다. 다른 카테고리에서는 숨는다
   (앨범은 정렬이 아니라 보는 방식이다). 앨범에서 다른 보기 버튼을 누르면 앨범 이전에
   보던 목록 형태로 돌아간다.
2. **앨범 자켓으로 나열된다**: '앨범'을 고르면 영상 목록 대신 자켓 카드가 깔린다.
   자켓·발매일은 인터넷(iTunes, 로그인·키 불필요)에서 받아 오고, 못 받으면 그 앨범
   대표 영상의 썸네일을 대신 쓴다. 카드에는 '내가 가진 곡 수 / 전체 수록곡 수'가 뜬다.
3. **앨범을 열면 수록곡이 보인다**: 자켓·앨범 설명(가수·장르·발매일·수록곡 수)과 함께
   수록곡이 번호 순으로 나열된다. 내 라이브러리에 있는 곡은 자동으로 그 자리에 매칭되며,
   영상 제목에 "(Official Audio)" 같은 꼬리표가 붙어 있어도 알아서 찾아 붙인다.
4. **없는 곡은 앱이 찾아서 채운다**: 라이브러리에 없는 수록곡은 앨범을 열 때
   백그라운드로 공식 음원 영상을 찾아 채운다(찾은 결과는 저장돼 다음에 다시 찾지 않는다).
   원하면 '빠진 곡 찾기' 버튼으로 다시 시도할 수 있다.
5. **앨범 곡을 한꺼번에 담는다**: 수록곡 목록 위의 '＋ 현재 카테고리에 등록'을 누르면
   아직 라이브러리에 없어 앱이 찾아 둔 곡들이 지금 보고 있는 카테고리로 모두 등록되고,
   등록된 곡은 곧바로 '내 등록'으로 바뀐다(가수·앨범 정보도 함께 기록돼 이 앨범에 남는다).
6. **어디서 온 곡인지 표시된다**: 수록곡마다 '내 등록'(내가 담은 영상) · '자동 매핑'
   (앱이 찾은 스트리밍 영상) · '없음'(아직 못 찾음) 배지가 붙는다.
7. **앨범 단위로 이어 재생한다**: '▶ 앨범 재생'을 누르면 첫 곡부터, 수록곡을 클릭하면
   그 곡부터 앨범이 이어서 재생된다(내 영상과 자동 매핑된 스트리밍 영상이 섞여 있어도
   그대로 이어진다).
8. **앨범 정보가 없는 노래도 앨범을 찾아 준다**: 노래 정보에 앨범이 비어 있으면 가수·제목으로
   앨범을 추정해 채운다. 못 찾은 곡은 '앨범 미상'에 모이고, 같은 곡을 반복 조회하지 않는다.
9. **뒤로/앞으로 가기가 앨범 화면에도 적용된다**: 앨범 그리드·앨범 상세도 화면
   기록에 남아, 마우스 뒤로가기나 ‹ 버튼으로 직전 화면(앨범 그리드 → 목록, 앨범 상세 →
   그리드)으로 돌아가고 앞으로가기로 다시 열 수 있다. 앨범을 재생하다가 뒤로 가면 앨범
   상세로 돌아온다.
10. **하위 카테고리까지 함께 본다**: 'Music > 가수 > 곡'처럼 나눠 담았어도 상위에서 앨범을
   보면 하위 곡이 모두 포함된다.

### v1.26+ — 받은 파일에 부가 정보 굽기

받아 둔 파일을 다른 플레이어·차량·휴대폰으로 옮겼을 때도 자막·표지·챕터·노래 정보가
따라가게 한다. 지금까지는 앱 안에서만 보이는 정보였다.

1. **설정 > 다운로드 > 파일에 포함**: 자막 언어(비우면 자막을 받지 않음)와 「자막을
   영상 파일에 포함」·「썸네일을 표지로 포함」·「챕터 정보를 포함」·「음원에 노래
   정보 기록」 네 가지를 켜고 끈다. 기본값은 모두 켜짐이며 자막 언어만 비어 있다.
2. **자막**: 지정한 언어의 자막을 받아 영상 파일 안에 넣는다. 사람이 단 자막이 없으면
   자동 생성 자막을 받는다. 구우면 `.srt` 파일은 남기지 않는다(플레이어가 같은 자막을
   두 번 잡아 중복 표시되는 것을 막는다). 음원(mp3·m4a)에는 자막 트랙을 담을 수 없어
   건너뛴다.
3. **표지·챕터**: 썸네일을 표지 이미지로, 챕터 구간을 챕터 메타데이터로 파일에 넣는다.
4. **음원 노래 정보**: 음원으로 받으면 라이브러리의 가수·앨범·노래 제목·발매년도·가사·
   표지가 태그(mp3=ID3, m4a=MP4 atom, flac/ogg=Vorbis)로 기록된다. 싱크 가사가 있으면
   시간 정보가 있는 LRC 형식으로 넣어 다른 플레이어에서도 줄이 따라 흐른다. 라이브러리
   에서 「노래로 표시」된 영상만 대상이다.
5. **실패해도 다운로드는 성공이다**: 태그 기록은 부가 산출물이라, 실패하면 로그만 남기고
   받은 파일은 그대로 둔다.

### v1.26+ — 설명 속 챕터를 클립으로

긴 영상의 챕터를 하나씩 손으로 시작·끝을 찍어 잘라내던 일을 없앤다.

1. **클립 탭 위에 '설명 속 챕터' 구역**: 영상 설명의 타임스탬프에서 찾은 구간을
   체크박스 목록으로 보여준다. 각 줄에 시작 시각과 제목이 뜨고, 마우스를 올리면
   시작~끝과 길이를 볼 수 있다. 기본은 전부 선택이며 '전체 선택/해제'로 한 번에
   바꾼다.
2. **찾은 게 없으면 구역이 아예 뜨지 않는다**: 챕터가 없는 영상이 대부분이라
   빈 상자를 남기지 않는다. 다운로드한 로컬 파일이 있어야 보인다(추출 대상이 없으면
   목록만 보여 줄 이유가 없다).
3. **고른 챕터를 각각 클립으로 저장**: '선택한 챕터 추출'을 누르면 순서대로 하나씩
   잘라 클립 목록에 추가한다. 진행 상황이 `(3/12) — 챕터 제목`으로 표시되고, 끝나면
   토스트로 알린다.
4. **한 구간이 실패해도 멈추지 않는다**: 실패한 챕터는 건너뛰고 나머지를 계속하며,
   완료 후 '9개 추출 완료 · 1개 실패'처럼 함께 알린다.
5. **오탐을 걸러낸다**: 본문 한복판의 "10:30에 촬영했습니다" 같은 시각 표기는 챕터로
   보지 않는다(타임스탬프가 줄 맨 앞이나 맨 뒤에 있을 때만 인정). 시각이 뒤로 가는
   줄도 건너뛴다.

### v1.26+ — SponsorBlock(스폰서 구간 건너뛰기·잘라내기)

영상 중간의 스폰서 광고·자기 홍보·구독 요청 구간을 넘긴다. 구간 정보는 SponsorBlock
공개 데이터베이스(사용자들이 모은 것)에서 받는다.

1. **재생 중 자동 건너뛰기**(기본 켜짐): 재생 위치가 구간에 들어가면 그 끝으로
   넘기고 "스폰서 광고 구간을 건너뛰었습니다" 토스트를 띄운다. 스트리밍·로컬 재생
   모두 같다.
2. **되감아 보면 다시 튕기지 않는다**: 한 번 건너뛴 구간은 다시 건너뛰지 않는다.
   그 구간을 일부러 보려는 사용자를 계속 밀어내면 볼 방법이 없다.
3. **다운로드 파일에서 잘라내기**(기본 꺼짐): 켜면 받은 파일에서 해당 구간을 실제로
   제거한다. 되돌릴 수 없으므로 기본은 꺼져 있다. 자막을 함께 굽는 경우 잘라낸
   만큼 자막 타이밍도 맞춰진다.
4. **카테고리 선택**: 스폰서 광고·자기 홍보·구독 요청·인트로·아웃트로·예고·잡담·
   음악 외 구간 중에서 고른다. 기본은 광고성 3종(스폰서·자기 홍보·구독 요청)이며,
   인트로·잡담은 그걸 보려고 튼 사람도 있어 기본에서 뺐다. 건너뛰기와 잘라내기가
   같은 목록을 쓴다.
5. **어떤 영상을 보는지 알려 주지 않는다**: 조회할 때 영상 ID를 그대로 보내지 않고
   해시 앞자리만 보낸다. 같은 앞자리를 가진 여러 영상의 결과가 함께 오므로 서버는
   어느 것인지 알 수 없다.
6. **실패해도 재생을 막지 않는다**: SponsorBlock이 응답하지 않거나 형식이 이상해도
   건너뛰기만 동작하지 않고 재생은 그대로 이어진다.
7. **YouTube 영상만 해당**: SponsorBlock이 YouTube만 다룬다.

### v1.26+ — 자막 전문 검색 & 시점 점프

"그 말 나온 데가 어디였더라"를 해결한다. 영상 자막을 색인해 두면 **어느 영상의 몇 분
몇 초에** 그 대사가 나왔는지 찾아 그 시점부터 바로 재생한다.

1. **상세화면 '자막' 탭**(5번째): 맨 위 검색칸에 말을 넣으면 그 말이 든 자막 줄만
   남고, 줄을 누르면 그 시점부터 재생된다(멈춰 있었으면 재생이 시작된다).
2. **라이브러리 검색에 자막이 포함된다**: 제목·태그·설명·메모·요약·노래 정보·가사에
   더해 자막까지 한 번에 찾고, 자막에서 일치하면 결과 카드에 **「자막」 배지**가 붙는다.
   부분 일치 규칙은 다른 속성과 같다("가정부"로 "가정부라고"를 찾는다).
3. **색인은 두 경로로 쌓인다**:
   - *공짜 경로* — 재생 중 자막을 켜면 이미 받아 온 자막이 그대로 색인된다(추가
     네트워크 없음).
   - *명시 경로* — 자막 탭의 「자막 가져오기」(또는 ⟳)를 누르면 그때 받아 온다.
   등록·일괄 임포트 때 자동으로 받지 않는다 — 영상당 네트워크 왕복이 있어 수백 건
   가져오기를 막는다.
4. **왜 비었는지 항상 말한다**: 아직 안 받은 영상 / 자막이 아예 없는 영상 / 검색어가
   안 맞은 경우 / 라이브러리에 담지 않은 스트리밍 영상 네 가지를 각각 다르게 안내하며,
   해결책이 없는 경우에는 「가져오기」 버튼을 숨긴다.
5. **한 영상에 언어가 여럿이면 따로 보관**하고, 다시 가져오면 그 언어를 통째로 바꾼다
   (자동 자막이 나중에 사람 자막으로 대체되는 일이 흔하다).
6. **영상을 지우면 자막 색인도 함께 사라진다**. 색인은 언제든 다시 받을 수 있는 파생
   데이터라 클라우드 동기화 대상이 아니다.

### v1.27+ — 전송 옵션(속도·병렬·프록시)과 예약 다운로드

1. **속도 제한**: 설정 > 다운로드 > 전송에 상한을 적는다("2M", "500K"). 비우면 무제한.
2. **조각 동시 수**: 고화질 영상은 조각으로 쪼개져 오므로, 조각을 여러 개 동시에 받으면
   체감이 크게 빨라진다(1이면 끔). 조각이 없는 영상에는 저절로 적용되지 않는다.
3. **프록시**: `http://`·`socks5://` 주소를 적으면 그 경로로 받는다. 비우면 사용 안 함.
4. **예약 다운로드**: "정해진 시간대에만 받기"를 켜고 시작·종료 시각을 고르면 그
   시간대에만 다운로드가 시작된다. 23시~7시처럼 **자정을 넘기는 구간**도 된다.
   시간대 밖에서 요청한 작업은 대기줄에 남았다가 시간이 되면 자동으로 시작된다.
5. **동시 다운로드 수가 실제로 적용된다**: 예전에는 설정 화면에만 있고 아무 효과가
   없어(요청마다 곧바로 받기 시작) 사실상 무제한이었다. 이제 한도만큼만 동시에 받고
   나머지는 먼저 넣은 순서로 대기한다. 시작 전 작업을 취소하면 대기줄에서 빠진다.
6. **기다리는 이유를 화면이 말한다**: 게이트에 걸린 작업은 진행률이 영원히 0이라
   '0%'로 그리면 멈춘 것처럼 보인다. 카드에 **'대기 중'**을 띄우고, 목록 위에
   이유를 한 줄 적는다("예약 시간대(23시~7시)를 기다립니다 — 3건 대기" /
   "동시 다운로드 2개 제한 — 2건이 차례를 기다립니다").
7. **다운로드를 멈출 수 있다**: 카드를 우클릭해 취소한다(진행 중이면 "다운로드 취소",
   아직 안 시작했으면 "대기 취소"). 끝난 카드에는 뜨지 않는다. 그전에는 멈출 길이
   없어, 잘못 넣은 주소나 몇 시간짜리 녹화를 되돌리려면 앱을 꺼야 했다.

### v1.27+ — 사라진 원본 찾기

아카이브로 모아 둔 라이브러리에서 가장 아픈 지점은 "담아 둔 영상이 원본에서 사라진
것"이다. 라이브러리 정리 화면에 세 번째 탭을 추가한다.

1. **사람이 눌러야 시작한다**: 영상마다 인터넷에 한 번씩 물어보므로 수백 건이면 몇 분이
   걸린다. 창을 열자마자 자동으로 돌지 않고 「원본 확인 시작」을 눌러야 한다. 진행률이
   `37/240` 형태로 표시되고 도중에 「중지」할 수 있다.
2. **사라짐을 두 가지로 구분한다**: `삭제됨`(업로더가 내렸거나 YouTube가 지움)과
   `비공개`(아직 있지만 볼 수 없음). 비공개는 나중에 다시 공개될 수 있어 대응이 다르다.
3. **확인하지 못한 영상은 목록에 넣지 않는다**: 네트워크 실패·속도 제한·미지원 사이트는
   '확인 불가'이며 사라진 것으로 보고하지 않는다. 확인 못 한 것을 사라졌다고 알리면
   멀쩡한 영상을 지우게 된다.
4. **아무것도 기본 선택하지 않는다**: 지울지는 사람이 정한다. 체크한 영상은 기존
   「선택한 영상 삭제」로 중복 탭과 함께 한 번에 지워진다.
5. **YouTube 영상만 확인한다**(SponsorBlock과 같은 제약).

> **다운로드 아카이브(yt-dlp `--download-archive`)는 넣지 않는다.** 이 앱은 재생목록·
> 채널을 자체적으로 펼쳐 영상 단위로 받고, 이미 받은 항목은 다운로드 이력으로 건너뛴다.
> 아카이브 파일을 더하면 화면에 보이지 않는 두 번째 진실원천이 생겨 "왜 다운로드가
> 안 되지?"의 원인이 된다.

### v1.27+ — 다른 기기용으로 변환

받아 둔 파일이 폰·TV·차량에서 열리지 않는 경우를 위해, 상세화면 다운로드 탭에서
바로 변환한다.

1. **"어디서 볼 것인가"만 고른다**: 코덱·비트레이트를 직접 고르는 화면은 잘못 고르면
   결과가 재생되지 않으므로 두지 않는다. 프리셋 다섯 가지 — 일반 재생용(1080p),
   용량 줄이기(720p), 휴대용(480p), 음원만(mp3), 음원만(m4a).
2. **모든 영상 프리셋은 H.264+AAC+mp4**다. 이 조합만 사실상 어디서나 열린다.
3. **원본을 덮어쓰지 않는다**: 결과는 `제목 [프리셋].확장자`라는 새 파일이다. 변환은
   되돌릴 수 없으므로 결과를 확인한 뒤 원본을 지울지는 사용자가 정한다.
4. **작은 영상을 늘리지 않는다**: 480p 영상을 1080p 프리셋으로 바꿔도 해상도는
   그대로다(늘리면 화질은 그대로인데 파일만 커진다).
5. **진행률이 보인다**: 영상 길이에 비례해 퍼센트가 올라가고, 끝나면 토스트로 알린다.
   변환은 한 번에 하나만 돈다(ffmpeg 여러 개를 동시에 돌리면 저사양 PC에서 CPU가 먼저 막힌다).

### v1.28+ — 자막 일괄 색인

자막 검색은 색인된 영상만 대상이라, 이미 모아 둔 라이브러리에는 쓸 수 없었다.
설정 화면에 「자막 색인」 항목을 추가해 한 번에 채운다.

1. **현황을 먼저 보여준다**: "영상 240개 중 31개 색인됨 (남은 209개)".
2. **사람이 눌러야 시작한다**: 영상마다 인터넷에 한 번씩 물어보므로 수백 건이면
   10분을 넘긴다. 진행률이 `37/209`와 지금 확인 중인 제목으로 표시되고 언제든
   「중지」할 수 있다.
3. **이미 색인된 영상은 건너뛴다**: 중단했다가 다시 시작해도 하던 자리부터 이어진다.
   특정 영상을 다시 받고 싶으면 상세화면 자막 탭의 ⟳를 쓴다.
4. **끝나면 집계를 알린다**: "180개 색인 · 29개는 자막 없음". 중단했으면 그것도 함께
   표시하고, 현황 줄이 곧바로 갱신된다.
5. **앱을 닫으면 색인도 멈춘다**(협조적 중단이라 곧 끝난다).

### v1.28+ — 미디어 서버용 내보내기 (.nfo / .m3u)

모아 둔 메타데이터를 Plex·Jellyfin·Kodi가 읽을 수 있게 내보낸다. 이 앱이 **미디어
서버의 수집기**가 된다.

1. **설정 > 라이브러리 가져오기/내보내기**에 「미디어 서버용 내보내기…」 버튼.
   카테고리를 고르고, 재생목록을 저장할 위치를 정한다(취소하면 정보 파일만 만든다).
2. **정보 파일(.nfo)은 받아 둔 영상 파일 옆에 만든다**: 서버는 미디어 파일과 같은
   폴더의 같은 이름만 읽으므로 위치를 고를 여지가 없다. 제목·설명·채널·태그·업로드일·
   상영시간·썸네일·원본 주소가 들어간다.
3. **노래로 표시한 영상은 음악으로 내보낸다**: 가수·앨범이 함께 들어가고 제목은
   영상 제목이 아니라 **곡 제목**을 쓴다("(Official MV)" 같은 꼬리표가 음악 목록에
   남지 않는다).
4. **재생목록(.m3u)**은 고른 카테고리의 영상을 순서대로 담는다. 한글 제목이 다른
   기기에서 깨지지 않도록 UTF-8로 저장한다.
5. **받아 둔 파일이 없는 영상은 건너뛴다**: 서버가 읽을 미디어가 없으니 정보 파일만
   남겨 봐야 쓸모가 없다. 몇 개를 건너뛰었는지 결과에 함께 알린다.
6. **한 건이 실패해도 멈추지 않는다**: 읽기 전용 폴더 하나 때문에 전체가 무산되면
   어디까지 됐는지 알 수 없다. 실패한 수를 함께 보고한다.

### v1.29+ — 라이브 방송 녹화

방송 중인 영상을 받으면 일반 다운로드가 아니라 **녹화**로 다룬다. 둘은 성질이 달라
같은 규칙을 쓰면 어느 한쪽이 망가진다.

1. **예약 시간대·동시 다운로드 한도를 우회한다**: 방송은 지금 아니면 받을 수 없다.
   "밤에만 받기"를 켜 둔 상태에서 낮에 방송이 시작되면, 대기줄에 묶인 채 방송이
   끝나 버린다. 대신 **동시 녹화 수에 자체 상한(2)** 을 둔다 — 녹화는 몇 시간씩
   이어져 쌓아 두면 디스크가 먼저 찬다.
2. **녹화가 일반 다운로드 자리를 막지 않는다**: 동시 실행 한도를 셀 때 녹화는
   빼고 센다. 넣으면 장시간 녹화 하나가 큐를 통째로 멈춘다.
3. **진행 표시가 다르다**: 총 크기를 모르므로 퍼센트 대신 `1시간 23분 · 2.4 GB`처럼
   경과 시간과 받은 용량을 보여준다. 0%가 계속 떠 있으면 멈춘 것처럼 보인다.
4. **대기하게 된 작업만 방송 여부를 확인한다**: 곧바로 시작할 수 있으면 라이브든
   아니든 이미 받고 있으므로 물어볼 이유가 없다. 모든 다운로드에 메타데이터 조회를
   끼워 넣으면 흔한 경우가 1초씩 느려진다.
5. **예정된 방송은 녹화하지 않는다**: 시작 시각까지 기다리게 하면 그동안 화면에는
   '녹화 중'으로 보이고 워커도 잡혀 있다. 끝난 방송은 일반 다운로드로 받는다.

### v1.29+ — 음성 인식으로 자막 만들기

YouTube가 자막을 주지 않는 영상(오래된 영상, 자동 자막 미지원 언어)은 자막 검색의
사각지대였다. 영상의 소리를 듣고 자막을 만들어 그 구멍을 메운다.

1. **만든 자막은 기존 자막 색인에 들어간다**: 라이브러리 검색·자막 탭의 시점 점프가
   그대로 동작한다. 사용자에게는 '이 영상의 자막'일 뿐이다.
2. **YouTube 자막을 덮어쓰지 않는다**: 전사 결과는 별도 언어 키(`asr-…`)로 저장되어,
   나중에 YouTube 자막을 받아도 둘 다 남는다. 목록에는 어떤 모델로 만들었는지 적힌다.
3. **자막 탭의 대안 버튼**: 「음성 인식으로 만들기」는 **받아 둔 파일이 있을 때만**
   보인다(소리를 읽어야 하므로). 자막을 아예 못 구한 영상에서 가장 쓸모 있고,
   검색 결과가 없을 뿐인 경우에는 보이지 않는다.
4. **모델은 처음 한 번만 내려받는다**: 설정 → 「자막 색인」의 *음성 인식으로 자막
   만들기*에서 tiny(75MB) · base(145MB, 기본) · small(484MB) 중 고른다. 고른 모델을
   첫 사용 시 받아 `DATA_DIR/models/whisper`에 두고, 받는 중에는 크기를 함께 알린다.
   **고르는 값이 곧 디스크와 시간**이라 콤보에 용량을, 아래에 설명을 적는다.
5. **받아 둔 모델은 지울 수 있다**: 한 번 받으면 계속 남으므로(small은 484MB) 설정에서
   지우는 길을 둔다. 목록·용량 판정은 **파일만 본다** — 모델을 실제로 올려 판정하면
   설정 화면을 여는 것만으로 수백 MB가 붙잡힌다.
6. **시간이 걸리고, 멈출 수 있다**: 영상 길이의 6~35%(모델에 따라). 진행률을 퍼센트로
   보여주고 자막 탭의 「중단」으로 멈출 수 있으며, 중단해도 **그때까지 인식한 부분은
   자막으로 남는다**. 다만 모델을 내려받는 동안에는 중단 버튼을 띄우지 않는다 —
   협조적 중단이 세그먼트 경계에서만 걸려, 눌러도 몇 분간 반응이 없으면 고장처럼
   보인다. 중단해서 결과가 없는 것과 끝까지 듣고 말을 못 찾은 것은 구분해 알린다.
7. **말이 없으면 그렇게 알린다**: 음악만 있거나 소리가 없는 영상은 결과가 비는데,
   실패와 구분해서 안내한다.

> **설치 파일이 커진다**: 음성 인식 라이브러리를 빌드에 포함하므로 설치본이 약
> 134MB → 250~300MB가 된다. 실행 중에는 `pip install`을 할 수 없어(PyInstaller로
> 얼린 앱에는 설치할 site-packages도 pip도 없다) 라이브러리는 미리 넣고 **모델
> 가중치만** 실행 중에 받는 구조다.

### v1.29+ — 자막에서 볼 만한 구간 찾기

긴 영상에서 "어디부터 볼까"를 줄여 준다. 클립 탭의 「자막에서 볼 만한 구간 찾기」를
누르면 구간을 제안하고, **고르는 것도 자르는 것도 사람이 한다**.

1. **제안일 뿐이다**: 자동으로 잘라 두지 않는다 — 쓰지도 않을 파일이 쌓인다.
   제안 결과는 챕터와 **같은 체크박스 목록**에 들어가므로, 고르고 한 번에 추출하는
   기존 흐름을 그대로 쓴다(새로 배울 것이 없다).
2. **자막이 있어야 한다**: 자막 색인(YouTube 자막이든 음성 인식이든)을 읽는다.
   없으면 "자막을 먼저 가져오거나 만들어 주세요"로 안내한다.
3. **무엇을 보고 고르나**: 같은 시간에 말이 많이 나온 구간(설명·핵심일 확률이 높다)과
   업로더가 나눈 챕터 경계. 챕터와 맞는 구간은 그 제목을 그대로 쓴다.
4. **인사말 구간은 뺀다**: 시작부의 인사·구독 요청은 빠르게 말해 글자가 몰리지만 볼
   이유가 없다. 다만 다른 후보가 하나도 없으면(짧은 영상) 그거라도 제안한다.
5. **외부 AI를 쓰지 않는다**: 영상마다 비용·대기가 생기고 오프라인에서 동작하지 않는데,
   얻는 것은 '그럴듯한 순서'뿐이다. 이미 손에 있는 자막만으로 계산하므로 즉시 나온다.

### v1.28+ — 약속만 있고 없던 것들 ①: 백업·알림·북마크

기획서에 적혀 있는데 실제로는 없던 기능들을 채운다. 사용자는 문서·설정 파일을 보고
있다고 믿을 수 있어, 없는 것보다 나쁘다.

1. **라이브러리 DB를 하루 한 번 백업한다**: `data/backups/library-YYYYMMDD.db`로
   남기고 최근 7개를 보관한다. 같은 날 앱을 여러 번 켜도 복사는 한 번이고, 창이 뜬
   뒤 배경에서 돌아 시작을 막지 않는다. **라이브 파일을 그냥 복사하지 않는다** —
   WAL 사이드카까지 반영된 정합 사본을 만든다(그러지 않으면 어제까지의 DB가 된다).
   백업 폴더는 클라우드 동기화의 충돌 백업도 쓰는 곳이라, **우리 이름의 파일만**
   세고 지운다.
2. **트레이 알림**: 다운로드는 몇 분~몇 시간이 걸리고 그동안 사용자는 이 앱을 보고
   있지 않다. 끝나면 트레이로 알린다. **창이 앞에 있을 때는 보내지 않는다** —
   보고 있는 사람에게는 이미 토스트가 있고, 같은 소식이 두 번 뜨면 알림을 꺼 버린다.
   트레이가 없는 데스크톱에서는 기능만 조용히 빠진다(설정에서도 끈 채로 잠긴다).
3. **구독 채널 새 영상 감시**(기본 꺼짐): 배경에서 주기적으로(기본 30분, 최소 10분)
   피드를 조용히 훑어 새 영상이 있으면 알린다. **보고 있는 목록을 건드리지 않는다.**
   "지난번 이후" 판정은 날짜가 아니라 **주소 비교**다 — `published_at` 표기가 출처마다
   달라 날짜로 재면 조용히 틀린다. 처음 켠 회차는 알리지 않는다(설치 직후 피드 전체를
   알리면 사용자가 알림을 꺼 버린다).
4. **브라우저 북마크(HTML) 가져오기**: Chrome·Edge·Firefox·Safari가 모두 같은 형식
   (Netscape Bookmark File Format)으로 내보내므로 파서 하나로 받는다. 북마크에는
   영상이 아닌 링크가 섞여 있는데, **우리가 걸러 버리면 yt-dlp가 받을 수 있는 사이트를
   막는 꼴**이라 흔한 영상 호스트만 미리 체크해 두고 나머지는 사용자가 고른다.
   북마크 폴더 이름을 함께 보여 어느 카테고리에 담을지 판단하게 한다. 한 번에 200개까지.

### v1.29+ — 약속만 있고 없던 것들 ②: 복합 필터와 저장된 검색

1. **복합 필터**(v1.28.0에 먼저 들어갔다): 업로드 날짜·영상 길이·채널·다운로드 여부·
   시청 여부·즐겨찾기로 목록을 좁힌다. 엔진(`SearchQuery`·리포지토리 SQL)은 이미
   있었는데 화면에서 넘기는 곳이 없어 쓸 수 없었다. 툴바의 「필터」로 접었다 펴고,
   **걸린 개수를 버튼에 적어** 접혀 있어도 알 수 있게 한다. 날짜·길이는 직접 입력이
   아니라 프리셋이다 — 두 칸을 손으로 채우게 하면 대부분 안 쓴다.
2. **저장된 검색**: 자주 쓰는 조건("안 본 긴 영상", "침착맨 최근 1주")에 이름을 붙여
   두고 툴바의 「저장된 검색」에서 되부른다. 이름 바꾸기·삭제도 같은 메뉴에 있다.
   되부르면 검색어와 필터 막대가 저장된 대로 복원되고, 막대가 함께 펴져 **무엇으로
   좁혔는지 보인다**.
3. **조건은 값이 아니라 프리셋 키로 저장한다**: "최근 1주"를 `published_from=
   "2026-09-12"`로 굳히면 다음 달에 열었을 때 그 주의 영상만 나온다. 사용자가 기대한
   것은 "지금으로부터 최근 1주"다 — 되부를 때마다 오늘 기준으로 다시 푼다.
4. **저장을 거절하지 않는다**: 이름이 겹치면 번호를 붙인다. 저장은 곁가지 행동이라
   거기서 막아 세우면 하려던 일(영상 찾기)의 흐름이 끊긴다. 다만 조건이 하나도 없는
   검색은 저장하지 않는다(되불러도 아무 일이 없다). 상한은 50개이고, 넘기면 가장
   오래된 것을 밀어낸다 — 거절하면 사용자는 뭘 지워야 할지 모른 채 막힌다.
5. **깨진 항목 하나가 목록 전체를 막지 않는다**: 앱 버전을 오르내리며 필드가 바뀌거나
   사용자가 DB를 손볼 수 있다. 모르는 키는 버리고 빠진 키는 기본값으로 채운다.

### v1.29+ — 자막을 한글로 옮기기

외국어 영상에 자막이 있어도 읽지 못하면 없는 것과 같다. 음성 인식으로 만든 자막도
마찬가지다 — 소리는 들었는데 뜻을 모른다. 가사에만 쓰던 번역기를 자막에도 쓴다.

1. **원문은 그대로 남는다**: 번역본은 별도 언어 키(`tr-ko`)로 저장한다. 번역이
   엉망일 수도 있고, 원문으로 검색하고 싶을 수도 있다(음성 인식이 `asr-…`를 쓰는
   것과 같은 이유). 둘 다 라이브러리 검색과 시점 점프에 쓰인다.
2. **번역본을 다시 번역하지 않는다**: 뜻이 뭉개진다. 번역할 원본 목록에서 번역본은
   빠지고, 원본 자막이 없으면 버튼 자체가 뜨지 않는다.
3. **이미 한국어면 하지 않는다**: 왕복만 낭비하고 결과도 원문보다 나빠진다
   (번역기가 문장을 다시 쓴다).
4. **묶어 보내되 정렬을 확인한다**: 번역기는 한 줄씩 호출하는 설계라(가사 40줄 기준)
   자막 수백 줄을 그대로 보내면 왕복이 그만큼 난다. 40줄씩 묶어 보내고, 돌아온 줄
   수가 맞지 않으면 **그 묶음만 한 줄씩 다시** 한다 — 억지로 맞추면 엉뚱한 시점에
   엉뚱한 말이 뜨는데, 그건 틀렸다는 티조차 나지 않는다.
5. **실패한 자리는 원문을 남긴다**: 빈 줄로 두면 그 시점에 자막이 사라져, 번역이
   실패한 것인지 원래 말이 없는 것인지 알 수 없다.
6. **시간이 걸리고 멈출 수 있다**: 진행률을 퍼센트로 보여주고, 중단해도 그때까지
   옮긴 부분은 남는다.

### v1.29+ — 다운로드 프리셋(받는 방식 골라 쓰기)

같은 사람이 영상을 받는 방식은 몇 가지로 갈린다 — 보관할 것은 화질 높게 자막까지,
음악은 음원만 태그 붙여서, 잠깐 볼 것은 가볍게. 전역 기본값 하나뿐이라 그때마다
설정 화면을 오가야 했다.

1. **내장 프리셋 세 가지**: 보관용(1080p·자막·챕터) · 음악(m4a·표지·태그) ·
   가볍게(720p·광고 잘라내기). 빈 목록에서 시작하면 무엇을 만들 수 있는지 모른다.
2. **지금 설정을 프리셋으로 저장**: 설정 화면의 화질·형식·자막·굽기를 그대로 굳힌다.
   이름이 겹치면 번호를 붙인다(거절하지 않는다).
3. **프리셋은 '어떤 파일을 원하는가'만 정한다**: 화질·형식·자막·굽기. 속도 제한·
   프록시·조각 수 같은 **전송 옵션은 프리셋과 무관**하게 전역 설정을 따른다 —
   회선의 성질이라 무엇을 받든 같고, 프리셋마다 두면 "왜 이 프리셋만 느리지"가 된다.
4. **고른 방식을 호출부가 이긴다**: 화질 메뉴처럼 그 자리에서 방식을 지정하면
   프리셋보다 그것이 우선한다. 지정하지 않은 다운로드만 프리셋을 쓴다.
5. **내장은 지우는 대신 숨긴다**: 코드에 있는 것을 설정으로 없앨 방법이 달리 없고,
   안 쓰는 항목이 목록에 남으면 고르기를 방해한다. 고쳐 쓴 내장은 숨김보다 우선한다.
6. **사라진 프리셋을 가리켜도 죽지 않는다**: 설정에 키만 남았거나 값이 낡았으면
   전역 설정으로 떨어진다. 모르는 화질 값은 낮추지 않고 "가능한 가장 좋은 것"으로 본다.

### v1.29+ — 워치 폴더(떨구면 알아서 담기)

브라우저에서 주소를 앱까지 끌어다 놓으려면 앱이 떠 있어야 한다. 폴더 하나를 정해
두면 앱이 꺼져 있어도 거기 모아 뒀다가 켤 때 한꺼번에 담는다.

1. **윈도우에서는 끌어다 놓는 것만으로 끝난다**: 브라우저 링크를 폴더로 끌면
   `.url` 파일이 생기고, 앱이 그 안의 주소만 뽑아 담는다(그 형식에는 아이콘 경로도
   들어 있어 통째로 훑으면 엉뚱한 것까지 주소로 잡힌다).
2. **`.txt` · `.html`도 받는다**: 주소를 줄줄이 적어 둔 메모나 북마크 내보내기 파일.
   폴더 안의 다른 파일(사진·문서)은 건드리지 않는다.
3. **복사 중인 파일은 미룬다**: 수정된 지 3초가 안 된 파일은 다음 회차로 넘긴다 —
   복사 중에 읽으면 주소가 잘린 채 들어오고, 그건 되돌리기 어렵다.
4. **담은 파일은 '처리됨' 폴더로 옮긴다**: 기록을 따로 두면 그 기록과 실제 폴더가
   어긋난다. 옮기면 폴더만 봐도 무엇이 처리됐는지 알 수 있고, 다시 담고 싶으면 도로
   꺼내면 된다. 같은 이름이 있으면 번호를 붙여 **덮어쓰지 않는다**.
5. **주소가 없는 파일은 그대로 둔다**: 실수로 넣었거나 아직 채우는 중일 수 있고,
   말없이 옮기면 사용자에게는 파일이 사라진 것으로 보인다.
6. **설정이 사실대로 말한다**: 지정한 경로에 폴더가 없으면 그렇게 알린다. 30초마다
   훑고, 한 번에 100건까지 담는다(각 건이 인터넷 조회를 한 번씩 한다).


### v1.32 — 앱 내 고화질 스트리밍 재생 & 상세 설명서

**고화질 재생**

1. **기본 화질이 1080p다.** 예전 기본값("자동 (빠른 재생)")은 영상과 소리가 함께
   담긴 포맷만 골랐는데, 그런 포맷은 360p 하나뿐이라 원본이 4K여도 늘 360p로
   재생됐다. 이름이 지키지 못할 약속을 하고 있었다.
2. **고화질도 내려받지 않는다.** 필요한 만큼만 받아 흘려보내며 합치므로 몇 초 안에
   재생이 시작된다. 전체를 받아 두고 트는 예전 방식은 **폴백**으로만 남는다.
3. **버티지 못하면 스스로 내려간다.** 영상 제공처가 앞서 읽는 것을 막는 경우가 있어,
   같은 자리에서 되풀이해 끊기면 말없이 "받아 두고 재생"으로 바꾼다(준비 표시를 띄운다).
   이 판정은 영상마다 새로 한다.
4. **선택한 화질은 세션 동안 유지된다.** 저사양 PC에서 버거우면 낮춰 두면 된다.

**상세 설명서**

1. **README는 개요만 담는다.** 화면별 사용법과 갈무리는 `docs/manual.md`로 옮긴다.
2. **F1로 연다.** 어느 화면에서든 F1을 누르면 기본 브라우저로 상세 설명서가 열린다.
   설정 → 도움말의 단추도 같은 곳을 연다.
3. **오프라인에서도 열린다.** 설치본에 HTML이 함께 들어가고, 그것이 없을 때만 저장소
   문서로 보낸다 — 인터넷이 없어도, 그리고 **지금 깔린 버전의** 설명서를 본다.
4. **갈무리는 자동으로 만든다.** 표본 자료를 심은 임시 DB로 실제 화면을 그려 저장하므로
   화면이 바뀌면 다시 돌리기만 하면 되고, 사용자의 실제 라이브러리는 찍히지 않는다.

### v1.32.1 — 설명서 갈무리 격리

v1.32.0 갈무리에 **사용자의 실제 즐겨찾기 항목**이 찍혀 나갔다. 갈무리를 만들 때 DB만
임시본으로 바꿨는데, 이 앱은 사용자 자료를 세 곳(DB·`config.yaml`·OS 사용자 데이터
경로의 즐겨찾기 파일)에 나눠 두기 때문이다.

1. **`OVC_DATA_DIR` 하나로 셋을 함께 옮긴다.** 갈무리 스크립트가 그 변수만 세우면
   사용자의 실제 자료는 읽히지도, 찍히지도 않는다.
2. **샌드박스는 프로젝트 안에 둔다.** 윈도우 임시 폴더는 사용자 홈 아래라, 저장 경로를
   보여 주는 설정 화면에 이번엔 사용자 이름이 찍혔다.
3. **다운로드 화면 갈무리에도 표본을 심는다.** 빈 화면은 설명서로 쓸 수 없다.
